# 基础工作区写入保护设计
> Task version: v4

守卫只处理实际能够取得目标路径的宿主编辑事件，以事件 cwd 与目标实际位置确定 Git 工作树；以 Git 对 linked worktree 的判断区分基础与任务工作区，不以分支名猜测。仅在目标仓库启用 TaskFlow 时生效，匹配整个 patch 每个目标及移动两端；无法确定目标时采用可解释的拒绝策略，不影响非相关仓库。拒绝只使用宿主支持的 deny 格式，不授予权限。

Todo intake 等基础工作区操作要有明确且可验证的例外：由现有专用命令或非被守卫工具路径执行，不通过简单的可伪造标志放行。发布编辑例外按用户要求延后至 TF-20261109-ccbb96；当前守卫可能拦截发布编辑。Shell 和其他未被 hook 观察的写入不声称受保护。所有宿主的目标路径、名称和回复契约需据文档与可运行测试适配；实测与文档推断分开。

## 宿主权限隔离

优先研究宿主是否支持基础工作区只读且任务 worktree 可写的权限模型，测试有效策略和操作结果；TaskFlow 只能按宿主公开能力建立或验证权限，无法验证时不能宣称已隔离。权限覆盖本地命令，MCP、已批准的提权和其他工具需单独评估。用户已同意该方向，具体接入方案必须以可复现实验和宿主能力为依据。

## 非阻断变化检测

对可观察的 shell 调用建立前后状态比较，不记录文件内容；提示仅说明基础工作区在观察窗口变化，不能判定变更来源。保证已有脏工作区、并行调用、失败、无权限、特殊文件及大目录下的行为可解释；探测失败不报告未变化。不得阻止操作或自动更改用户文件。若宿主事件无法可靠配对或不可安全记录基线，标为未支持而不声称覆盖。
