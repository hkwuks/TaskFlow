# 基础工作区写入保护设计
> Task version: v7

## v7 待批准方案
提供用户主动执行的授权命令，将具体基础工作区文档路径登记为一次性许可；守卫仅对所有目标均获许可的普通编辑放行，拒绝删除、移动、混合未授权路径及不可解析的 patch。完成一次匹配后消费许可，失败时默认拒绝。授权命令和许可文件可被拥有相同文件权限的进程调用或修改，不能作为防恶意 Agent 的安全边界；用户须明确授权，不能仅凭模型判断非开发工作自动发放许可。并发与路径规范化须有针对性验证；不能安全识别时拒绝。

## 工作树候选发现
在已有仓库检查中独立列出已提交归档的工作树候选，兼顾未合并分支；标识脏状态及不可检查状态，不称其为空闲或可安全复用。新任务引导明确先检查候选，再核实空闲与交接前置条件；确认后仍使用 reuse-worktree 的现有事务，禁止自动切换。检查仅报告，不修改工作树或引用。

守卫只处理实际能够取得目标路径的宿主编辑事件，以事件 cwd 与目标实际位置确定 Git 工作树；以 Git 对 linked worktree 的判断区分基础与任务工作区，不以分支名猜测。仅在目标仓库启用 TaskFlow 时生效，匹配整个 patch 每个目标及移动两端；无法确定目标时采用可解释的拒绝策略，不影响非相关仓库。拒绝只使用宿主支持的 deny 格式，不授予权限。

Todo intake 等基础工作区操作要有明确且可验证的例外：由现有专用命令或非被守卫工具路径执行，不通过简单的可伪造标志放行。发布编辑例外按用户要求延后至 TF-20261109-ccbb96；当前守卫可能拦截发布编辑。Shell 和其他未被 hook 观察的写入不声称受保护。所有宿主的目标路径、名称和回复契约需据文档与可运行测试适配；实测与文档推断分开。

## 宿主权限隔离

v6 归档边界：仅总结已合并与已验证的行为；真实宿主异步提示、剩余宿主对齐和未证明的权限边界由 TF-20261109-293987 跟踪，不把它们标为已验证。

优先研究宿主是否支持基础工作区只读且任务 worktree 可写的权限模型，测试有效策略和操作结果；TaskFlow 只能按宿主公开能力建立或验证权限，无法验证时不能宣称已隔离。权限覆盖本地命令，MCP、已批准的提权和其他工具需单独评估。用户已同意该方向，具体接入方案必须以可复现实验和宿主能力为依据。

## 非阻断变化检测

对支持异步 hook 的宿主，在 shell 调用后异步检查基础工作区的 Git 状态，不保存快照或记录文件内容。发现 Todo 以外未提交改动时提示核对，明确改动可能早已存在或来自其他进程；检查失败提示无法判断。此方式不比较前后状态，可能重复提醒，也可能漏掉被忽略或短暂出现后消失的文件，不影响命令启动或自动更改用户文件。未证实异步 hook 的宿主如实标记未接线。
