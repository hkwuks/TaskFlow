# Spec — 共享缓存与安全复用 worktree
> Task version: v1

## Objective and Success Criteria
在授权范围内减少重复下载；为串行任务复用已完成归档且归档记录已提交的工作树，同时保持各任务的文件、分支和证据隔离，并独立处理已合并本地分支的清理。

## Architecture Boundaries and Responsibilities
- TaskFlow Skill 在任务进入前指导查找和使用工具原生缓存，识别下载、环境和构建输出，不自动改全局配置。
- 显式复用命令负责检查 Git 工作区、基线、切换和证据账本；调用者确认该工作区无人占用。普通 Git 切换不会被声称具有 TaskFlow 账本隔离保障。
- 各宿主原有能力/外部证据 hook 与审批命令继续负责自己的证据读写；复用流程不得替它们创造证据。
- 本仓库 `CONTRIBUTING.md` 只负责本仓库自身流程，插件规则放在 `skills/taskflow/`、`hooks/`；两者须一致。

## Project Structure / Affected Files
`skills/taskflow/SKILL.md`、`skills/taskflow/references/runtime.md`、`hooks/task` 或专用复用命令、`hooks/archive`、`hooks/repository-check`、`hooks/prompt-reminder`、`CONTRIBUTING.md` 及相关 smoke / Windows 测试、hook 清单。按调用关系复核 evidence、external、released、declarations、version-baselines 和恢复路径；仅更改确有必要的文件。

## Interfaces, Data Flow, and Contracts
- 调用者明确目标 worktree、旧分支、已核实 base 与新分支；先确认无其他活动会话或写入者。不得以 Git clean 推断无占用。
- 复用前必须验证原任务已完成归档、归档文档及 Todo 指向一致，归档记录在当前分支已提交，且没有被占用的活动任务；再核对工作区已提交、索引未隐藏变化、无未跟踪变化、子模块无本地变化，检查被忽略项目；目标分支不得已存在或被其他 worktree 使用。核实最新目标 `main` 并固定其提交 SHA；先用 `git checkout --no-overwrite-ignore --detach <main-sha>` 切到该提交，再用 `git switch --no-track -c <new> <main-sha>` 创建新分支。这样无需在复用树检出已被主工作树使用的 main；不使用 force / -B / reset。两个切换动作不创建提交、不改写历史或重置任何引用；新分支从 main SHA 起步而非旧分支 HEAD，且不自动追踪旧分支。旧分支未合并的提交不会自动带入；如果旧分支已在 main 历史中，正常共同历史仍会保留。分离 HEAD 仅为受保护的中间状态，创建新分支并验证前禁止开始新任务或提交；失败时保留 journal 并阻断后续工作。
- 原任务归档并合并后，若需要立即清理本地分支而保留工作树，可在确认安全后受保护地将工作树切到 base 的分离 HEAD，再在合并验证且已有删除授权后执行 `git branch -d <old>`；拒绝或 squash/rebase 无法证明时保留分支并报告。也可先复用于新任务、再清理旧分支；未经合并不得删除。
- 选择“交接时保存并恢复账本”方案，而非仅依赖干净状态：在该 worktree 的 Git 元数据内，把原任务现有 `evidence`、`released`、`declarations`、`external` 及其恢复所需记录作为不可覆盖的原样快照，明确关联原任务 ID 和原分支；新任务获得独立空账本。`version-baselines` 保持原位并按任务保留。返回旧任务时恢复其账本；快照无法唯一归属、已存在不同内容或不可验证时停止，绝不猜测或丢弃历史。
- 交接顺序：先检查原任务归档和提交、当前工作树及目标；取得交接锁并记录原任务、原 HEAD、目标、账本位置及阶段；完整保存并校验旧账本后，先以防忽略文件覆盖的 Git checkout 将 HEAD 分离到已核实 main SHA，再从同一 SHA 创建不自动追踪旧分支的新分支；建立新任务账本并核对当前 HEAD、基线和证据边界后，才报告成功。旧账本和 journal 的实际路径、状态格式由实现明确公开并可供恢复检查；所有 Git 元数据路径必须在允许操作范围内，否则不进行交接。
- 复用事务中的账本读取、审批/门禁与写入必须与交接互斥；只给复用命令加锁不足以阻止旧会话写入。能力与外部证据 hook 不得等待锁来输出日志：锁不可用时按其不阻塞契约跳过记录；门禁与审批在交接中或 journal 不完整时拒绝继续。调用方仍须确认无其他活动会话，因为锁不能保证用户或 Git 外部进程不会写工作树。
- 任一步失败或进程中断时，journal 保留已完成阶段和恢复所需快照；恢复前核对当前 HEAD、旧分支和快照，提供明确的继续或回退入口；状态有歧义则拒绝自动恢复，不删除文件、重置分支或伪称原子。旧任务账本及版本基线始终可审计、可恢复。
- 分支引用和提交树校验：切换前记录 `refs/heads/main`、原分支引用及其提交、固定的 main SHA；分离 HEAD 和创建新分支后，确认 main 引用、原分支引用均未改变，且新分支起点严格等于固定 main SHA；不创建额外提交，不做 merge、rebase、reset 或 cherry-pick。若引用因并发变化，停止并保留恢复记录，绝不将他人正常更新重置回旧值。
- 合并边界：未合并旧分支的提交不会因从 main 创建新分支而进入新任务；若新任务依赖这些提交，应明确将依赖视为未满足，不假定已包含。main 或其他任务后续产生并行修改仍可能形成普通合并冲突；失败时保留 Git 冲突状态和原数据，不能承诺零冲突或自动覆盖解决。
- 分支清理先核实远端 base 的当前提交及旧分支确已进入该 base；不能仅凭 `git branch -d` 的成功推断已合并，因为它可能按分支 upstream 判断。工作树先安全切离，确认已授权后执行 `git branch -d`；因 squash/rebase 不满足祖先关系或 Git 拒绝时保留并报告，不自动 `-D`。
- 缓存操作先检查工具已有配置、缓存位置、资源及允许的读写路径，采用工具自身支持的缓存和按次配置；区分 pip/npm/uv 等不同缓存及并发语义，不把某个工具的缓存目录当成通用目录。若仅有项目内写权限，则只能使用项目内经授权的位置；不得隐式写入项目外默认缓存、修改全局配置或清除缓存。没有安全可用的共享缓存时保持隔离，不能因缓存不可用阻断核心工作。

## Invariants and Compatibility
- 切换与复用不得重置或删除旧分支；清理阶段在合并核实与用户授权后独立使用 `-d`，失败则保留；新任务独占其工作区，主工作区、活动任务及用户忽略文件不被修改。
- 不改变已安装插件或用户全局配置；不添加兼容性垫片。已有 ledger 和基线保留，可审计、可恢复；不凭无依据证据通过门禁。
- 归档先于复用；合并后工作树保留待复用不妨碍已合并本地分支清理。若用户选择移除工作树，仍须遵守核验和删除授权。

## Validation and Error Semantics
- 阶段证据不能跨任务复用：覆盖旧未消费 evidence、相同域名 external、已释放与声明记录，以及旧任务恢复后的账本与版本基线；故障注入覆盖保存前、保存后、切到分离 HEAD 后、创建新分支后、建立新账本后，逐次确认 journal 阻断审批且旧数据不丢。
- 模拟证据写入与交接竞争：所有参与者使用同一互斥协议，锁繁忙时证据 hook 立即返回、门禁失败关闭；不能以阻塞或等待写日志实现互斥。
- Git 实仓夹具覆盖未归档任务拒绝、已归档已提交但未合并分支保留、归档已合并后保留工作树且安全删除本地分支、保护被忽略冲突、普通未跟踪/未提交、隐藏索引和子模块变化、重名分支、失败/中断、占用与锁；校验 `refs/heads/main` 和旧分支引用、旧提交图与文件不变，新分支起点为已核实 main SHA 且不追踪旧分支；在 fixture 中覆盖后续 main 变化产生普通冲突及旧分支未合并的情形。
- 缓存指导用隔离夹具或命令观察验证路径、工具缓存及不修改全局配置；不把下载次数或逻辑大小当作 SSD 物理写入。
- 平台限制与无权限环境明确报告；真实主工作区及其他 worktree 不作为破坏性测试夹具。

## Code and Test Constraints
复用现有 Bash/Git 架构和测试设施，无新依赖；Unix smoke 与 Windows 专用入口均覆盖新能力。测试直接验证实际行为和恢复，变更既有期望时记录其原有契约和原因。

## Design Decisions and Alternatives
不默认把 `.venv`、`node_modules` 或产物目录指向 main；不默认开启 sparse-checkout；不自动回收任何 worktree；本地分支经合并核实及授权后仍按原有安全规则清理。保留已归档、已提交但未合并的原分支，并用明确的存储隔离避免旧证据误用。

## Open Questions
无；具体文件路径及命令参数在不改变上述契约的范围内由现有接口决定。
