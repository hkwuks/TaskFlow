# 远程 Issues 待办
> Task version: v1
> Status: in_progress

## 目标
让项目可选择使用 GitHub 或 GitLab Issues 作为待办主记录，并保留 TaskFlow 任务的本地执行关联。

## Task Kind
- Kind: capability

## 已确认事实和用户决定
- 每个项目显式选择本地或远程模式；默认保持本地模式。
- 首版支持 GitHub 和 GitLab 官方云端与自托管实例；一个项目可连接多个 Issue 仓库。
- 查看时汇总已连接仓库的待办；创建时由用户选择目标。Issue 是远程模式的待办主记录，本地只保留任务执行所需关联。
- 支持创建、编辑 Issue，更新状态和标签。操作时读取远端，以远端为准，不做后台轮询。
- 用户接受 GitHub 等不提供写入条件保护时的剩余竞态：仅更新指定字段、写前后核对并明确提示，不能保证发现或阻止所有并发覆盖。
- TaskFlow 阶段用标签表示；完成或取消时关闭 Issue，保留其他标签。
- 项目仓库配置默认模式，单条 Todo 保留实际存储归属；切换默认模式不自动迁移现有条目。
- 用户可选择保留本地只读快照，标明时间及可能过期；本地关联始终保留，快照不能离线修改后自动覆盖远端。
- 本地迁移到远端时保留原条目并关联去重；远端切回本地时由用户选择复制并解除关联，不擅自关闭或删除 Issue。
- 远端不可用或权限不足时，远端更新操作明确失败，保留本地数据，恢复后由用户重试。
- 旧本地 Todo 原文件保留；用户按需选择条目迁移，不自动删除。连接信息保存在项目中，复用宿主已有登录，凭据不写入仓库。

## 需求与验收标准
- 本地模式保持现有工作流；明确选择远程模式后，可配置多个不同平台及自托管实例的仓库，凭据不进入项目文件、任务文档或日志。
- 汇总列表可区分不同实例、仓库和 Issue；排除 GitHub Pull Request，分页结果完整，部分仓库失败时显式报告不完整。
- 用户可选目标创建 Issue、编辑内容及标签、查看最新状态；不覆盖其他用户的无关标签或未修改字段。
- Issue 可进入 TaskFlow 任务生命周期，关联足以定位远端 Issue 和本地任务；TaskFlow 阶段标签与关闭、恢复行为可追溯。
- 本地与远端之间的失败、超时和结果不明均明确报告并可恢复；不确定结果不得盲目重试创建。并发修改尽可能识别并报告，但不声称能捕获读写窗口内的所有覆盖。
- 可选择已有本地 Todo 迁移到指定仓库；保留原文件并防止重复创建；已有关联和历史不丢失。
- 默认模式切换后，可识别各条现有待办的归属；已关联或迁移的本地和远程条目在汇总中去重。
- 可选快照只读、可选择关闭并明确过期状态；快照中不得记录凭据。
- 对 GitHub 与 GitLab 的各项操作、鉴权失败、分页、网络故障、并发修改及生命周期和迁移进行可重复验证；说明真实服务测试覆盖范围。

## External Facts
- Depends on external facts: yes
- Source: https://docs.github.com/en/rest/issues/issues
- What it settled: GitHub Issues 接口可能返回 Pull Request，需按 pull_request 字段排除；写操作需要相应权限。
- Source: https://docs.gitlab.com/api/issues/
- What it settled: GitLab 提供 Issue 创建、更新、标签及 state_event 状态操作；具体请求及权限需以选用的接口和实例版本核验。

## 范围之外
- 后台轮询、自动离线队列和删除 Issue。

## 风险与待定事项
- 本地文件与远端 API 无法组成单一数据库事务；需要定义部分成功和结果不明时的可恢复步骤。
- 已知限制：平台不提供原子条件更新时，读后写窗口仍可能覆盖并发改动；远端删除或转移须明确报告并保留关联，不自动认定完成。
