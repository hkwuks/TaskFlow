# 改善 TaskFlow 能力选择与问题解决效果
> Task version: v1
> Status: in_progress

## Goal

调查并改善 TaskFlow 在开发任务中选择适用能力、调查真实问题和审查计划的效果，避免把流程标记当成问题已解决。

- Kind: defect

## Requirements

- 从历史失败案例和现行实现重建复现条件，区分模型行为、提醒送达、宿主覆盖、记录校验与真实结果。
- 比较现有机制与候选方案，先实测再选择是否需要阻断；不把增添字段、标记或通过字符串测试当作最终效果。
- 衡量真实能力选择、实际调查、计划与原始问题的对应、最终产物；把工具调用与实际贡献分开。
- 覆盖 Spec 阶段：对照可发现的适用技能、是否主动评估并读取、是否将有用方法融入 TaskFlow 指定格式以及规格是否满足实际验收；不要求无条件调用指定名称的技能。
- 检查全部阶段的能力引导：需求定义（含问题调查、需求澄清和头脑风暴）、研究、设计、规划、实现、验证审查、完成归档；区分不适用、适合自行完成与确需引导的情况。
- 对七阶段逐一分析并修复证实影响正常选择或使用适合能力的缺口；可以采用跨阶段的共同修复，但每个受影响阶段须有对应验证，不以新增记录替代实际效果。
- 尊重用户授权：必要时可运行真实模型验证，具体发送内容与目标受自动审批约束；不外传私人数据或整个仓库。
- 保留 TaskFlow 固定标题及用户可用其他能力的自由，不强制凭名称调用无关能力。

## Acceptance Criteria

- 给出可复查的失败案例和根因或明确区分未证实假设，不把提示送达当采纳。
- 已确认的机制变更覆盖实际行为；提供真实案例或经允许的真实宿主对照，若不可运行不得声称效果已验证。
- 机械测试覆盖修改契约、异常和宿主边界，但不能替代模型和产物检查。
- 真实场景或受控对照包含规格编写时遗漏适用技能的案例及不需要该技能的简单反例；记录可用技能、选择与理由、实际读取及对规格的贡献，并检查规格内容，不能仅凭调用或 unaided 标记判定通过。
- 对七个阶段分别给出引导入口、可用能力匹配、实际覆盖和证据边界；对头脑风暴验证未定方向时的备选与取舍，以及方向已明确时避免重复发散。行为结论须基于相应真实案例或对照，不能把静态覆盖写成效果已验证。
- 对既有归档成果和真实宿主验证待办说明关系；不擅自关闭或改写其他任务。
