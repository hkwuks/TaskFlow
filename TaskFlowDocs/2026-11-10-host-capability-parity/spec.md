# 宿主能力对齐设计
> Task version: v1

## Boundaries
以宿主实际事件为输入、TaskFlow 自有记录为输出；工具自身是否运行由宿主负责。适配可观察事件，不以解析任意 shell 命令或普通文件读取作为真实 Skill 调用证明。

## Evidence
保留现有工作树内 evidence 队列及 task/version/stage 释放记录；显式声明写入同工作树的独立 `declarations`，按任务、版本、阶段和能力核对并单独显示，不触碰自动观测队列，避免并发追加时错配。来源标为 `declared`，不得伪装成 `invoke` 或 `unaided`；声明不声称经过宿主验证。重复或与既有释放冲突的声明必须拒绝或在审批时拒绝，不能跨任务消费或破坏已有记录。

用户已同意上述来源区分；宿主无法运行时完成可验证部分，并把未验证项单独列出。对真正可观察的事件直接适配其已核实的工具名、字段和 hook 接线，不从读取文件或 shell 文本推断 Skill 调用。

## Host Matrix
逐项复核 Claude Code、Codex、CodeBuddy、dsh、Trae：启动与提示、阶段门、能力证据、外部查证、基础工作区守卫与异步提醒。记录每项事件格式、宿主支持依据和真实运行/合成测试的区别；不得引入用户未授权的全局配置变更。

| 能力 | Claude Code | Codex | CodeBuddy | dsh | Trae |
| --- | --- | --- | --- | --- | --- |
| 阶段写前门 | 已接线 | 已接线，apply_patch | 已接线 | 已接线，小写和 patch 经合成事件测试 | 已接线 |
| 能力事件记录 | Skill / Agent / MCP 已接线 | MCP 已接线，经合成事件测试 | Skill / Agent / MCP 已接线 | skill / MCP 已接线，skill 经合成事件测试 | Skill / MCP 已接线 |
| 外部查证记录 | 已接线 | 已接线 | 已接线 | 已接线；合成 PostToolUse 事件可由现有记录器处理 | 已接线 |
| 基础工作区异步提醒 | 已接线，结果交给 Agent | 已接线 | 未接线、能力待核实 | 未接线、能力待核实 | 未接线、能力待核实 |

上表是静态接线状态，不代表真实宿主验证通过；`master` 的 dsh 源码也不能代替已安装版本。所有宿主的真实事件和显示结果以各自实验为准。

## Failure Semantics
不能可靠识别来源时报告未知，不伪造调用、自动放行或静默宣称对齐；原有非阻断提示不变。多工作树、并发、重复事件和失效存储必须有可解释行为。
